Foundations · read this first

The one idea that makes everything click.

Master this and the rest of the guide is just detail. It answers the question every designer new to AI keeps hitting: when do I use a prompt, when a skill, and when an agent?

Where AI actually helps

Before the how, the where. AI earns its place on design work that is structured, repeatable, or high-volume — and gets in the way on work that is taste, judgement, or a single irreplaceable decision. Knowing the line is what separates using AI well from using it everywhere.

Reach for it

  • Enumerating states — every empty, loading, error and overflow case for Acme's user table
  • Turning a described interaction into a state and variant matrix
  • First-draft UX copy, error messages, empty-state text
  • Accessibility audits against WCAG criteria
  • Dev handoff specs and acceptance criteria
  • Restructuring research notes into themes
  • Anything you've now typed three times

Keep it human

  • The core creative direction — what the product should feel like
  • Deciding which problem is worth solving at all
  • Taste calls: is this good, not just correct
  • Talking to real users and reading the room
  • The final say on anything shipping to people
  • Political and organisational judgement
The test

If you could write down the steps for a colleague to follow, AI can probably do it. If the value is in your judgement and the steps live only in your head, it can't — and shouldn't pretend to.

The ladder: prompt → skill → subagent

These aren't three unrelated features. They're the same thing at three levels of permanence. A task starts as words you type, and — if it earns it — climbs into a saved tool, then into delegated work.

1 · Prompt — you type it

A prompt is just what you write into Claude. No setup, nothing saved. It's the right tool the first time you do something, or for anything you'll only ever do once.

❯ List every state Acme's user-management table row needs:
  default, hover, selected, loading, error, empty, and
  no-permission. For each, the trigger and what changes.

Stay here when: the task is a one-off, or you're still figuring out what you even want. Don't save a prompt you'll never run again — that's just clutter.

2 · Skill — you save it

The moment you've typed something close to the same prompt a third time, it wants to be a skill. A skill is that prompt written once into a file, invoked with a /command. The reusable 90% lives in the file; you type only the 10% that changes.

# ~/.claude/skills/spec-interaction/SKILL.md
---
name: spec-interaction
description: Turn a described interaction into a state
  table, variant matrix, and open questions.
---
You are a staff product designer. Produce ONLY a state
table, a variant matrix, and the open questions.

Interaction: $ARGUMENTS

Now any session, on any project, you type ❯/spec-interaction Acme table row actions and get the same disciplined output. The Skills library is a set of these, ready to copy in.

The graduation rule

Typed something structurally similar three times? That's the signal to make it a skill. Not twice — twice might be coincidence. Three times is a pattern, and patterns are what you automate.

3 · Subagent — you delegate it

A subagent is a skill with its own room. It runs in a separate context window, with its own instructions, its own tool access, and its own permissions — then hands back just the result. You reach for one when a job is big enough, or noisy enough, that you don't want it cluttering your main session.

# ~/.claude/agents/a11y-reviewer.md
---
name: a11y-reviewer
description: Audits a screen against WCAG 2.2 AA. Use
  after any UI change. Reports blockers, then improvements.
tools: Read, Grep, Glob
---
You are an accessibility specialist. Review the design and
report contrast, keyboard, focus and target-size issues...

Reach for a subagent when: the task can run on its own (a full accessibility sweep), when it'd flood your session with output (reading a huge file), or when you want to run several checks in parallel. The easiest way to make one is the /agents command, which walks you through it.

One level up — for later

Beyond subagents sit agent teams: multiple agents that coordinate across sessions and message each other. It's powerful, experimental, and off by default — genuinely useful once you're fluent, and a distraction before then. This guide covers it last, on purpose.

Which rung do I reach for?

When you're unsure, this is the whole decision.

?
Doing it once, or still exploring?Use a prompt. Don't over-build.

Don't skip rungs

The temptation is to build a subagent for everything on day one. Resist it. Most of your value comes from a handful of good skills. Over-building agents makes Claude's automatic delegation less reliable, not more — a sprawling roster of specialists is harder to route than a tight one.
